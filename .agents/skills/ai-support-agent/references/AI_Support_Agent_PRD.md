# PRD — AI Support Agent

**Версия:** 1.0  
**Статус:** Draft / для согласования  
**Дата:** 2026-11-07  
**Формат продукта:** SaaS, multi-tenant, BYOK (Bring Your Own Key)

## 1. Обзор продукта

AI Support Agent — платформа для автоматизации клиентской поддержки с использованием моделей Google Gemini. Пользователи создают рабочие пространства, подключают собственный API-ключ Google AI Studio, загружают базу знаний, настраивают AI-агента и обрабатывают диалоги клиентов через виджет и API.

**Принцип BYOK:** для каждого рабочего пространства требуется собственный ключ Google AI Studio. Без действительного ключа генерация AI-ответов недоступна. Расходы на Gemini API относятся к проекту Google, которому принадлежит ключ, согласно условиям и тарифам Google.

## 2. Цели и метрики

### Цели
- Автоматизировать типовые вопросы поддержки без потери контроля человеком.
- Обеспечить быстрый запуск агента без программирования.
- Исключить общий API-ключ платформы для пользовательских запросов.
- Обеспечить прозрачность источников ответов и затрат.

### KPI
| Метрика | Цель MVP | Метод измерения |
|---|---:|---|
| Время первого AI-ответа (p95) | ≤ 10 сек при нормальной нагрузке | серверная телеметрия |
| Доля диалогов, решённых без оператора | ≥ 40% после настройки базы знаний | оценка исходов диалогов |
| Успешность проверки ключей | ≥ 99% для валидных доступных ключей | события подключения |
| Доступность приложения | 99.5% в месяц, исключая внешние сбои Gemini | мониторинг SLO |
| Доля ответов с подтверждёнными источниками в RAG-режиме | ≥ 90% | аудит цитирования |

Цели являются проектными гипотезами и уточняются после пилота.

## 3. Пользователи и роли

- **Владелец workspace:** создаёт пространство, добавляет/удаляет ключ, управляет тарифом и доступами.
- **Администратор:** настраивает агента, источники знаний, интеграции и правила эскалации.
- **Оператор:** просматривает обращения, принимает эскалации и отвечает вручную.
- **Конечный клиент:** задаёт вопросы через чат-виджет или интегрированный канал.

Роли проверяются на сервере; пользователь одного workspace не имеет доступа к данным другого.

## 4. Область MVP

### Включено
1. Регистрация, вход, workspace, RBAC.
2. Подключение и проверка личного API-ключа Google AI Studio.
3. Выбор доступной модели Gemini из актуального каталога.
4. Настройка агента: имя, язык, тон, инструкции, рабочие часы.
5. База знаний: текст, FAQ, PDF, URL; индексация и поиск по источникам.
6. RAG-ответы с ссылками на найденные источники и отказом от выдумывания фактов.
7. Web-чат, история диалогов, ручная передача оператору.
8. Панель обращений и базовая аналитика.
9. API и webhooks для интеграций.
10. Лимиты, аудит, мониторинг и безопасная обработка ошибок.

### Не включено в MVP
- Голосовые звонки и омниканальность уровня enterprise.
- Самостоятельное обучение или fine-tuning моделей.
- Автономное выполнение платежей, возвратов и иных необратимых операций.
- Обязательства по доступности или цене сторонних моделей.

## 5. Требования к моделям Gemini

**Целевые продуктовые версии:** Gemini 3.5, Gemini 3.6, Gemini 3.8.

**Критическое правило:** эти названия являются требованиями к желаемой поддержке, а не утверждением об их существовании или доступности в Google AI Studio. Приложение не должно подставлять выдуманные идентификаторы вида `gemini-3.5-*`, `gemini-3.6-*` или `gemini-3.8-*`.

### FR-MODEL-01 — Каталог моделей
- Сервер использует актуальный официальный Gemini API для получения списка моделей, доступных с ключом пользователя.
- Для каждой модели сохраняются фактический `model_id`, отображаемое имя, поддерживаемые методы, ограничения и статус доступности.
- В интерфейсе показываются только модели, совместимые с генерацией контента и доступные конкретному ключу.
- Целевые версии 3.5/3.6/3.8 активируются только после обнаружения подтверждённых официальных идентификаторов и успешного capability-check.
- Если ни одна целевая модель не доступна, интерфейс объясняет ограничение; альтернативные доступные модели можно предложить только с явного согласия пользователя.
- Нельзя молча заменять выбранную модель другой.

### FR-MODEL-02 — Выбор и отказоустойчивость
- Настройка модели на уровне агента; изменение отражается в новых сообщениях.
- При недоступности модели: понятная ошибка, повтор по политике backoff и возможность ручного выбора другой модели.
- Версия модели, параметры запроса, задержка и расход токенов (если возвращаются API) логируются без секретов и избыточных персональных данных.

## 6. Google AI Studio API Key — только актуальная интеграция

### FR-KEY-01 — Подключение
1. Владелец открывает **Settings → AI Provider → Google AI Studio**.
2. Вставляет личный API-ключ, выпущенный в Google AI Studio.
3. Система отправляет ключ по HTTPS на backend и проверяет его через актуальный официальный Gemini API.
4. Backend получает список разрешённых моделей и выполняет минимальный тест совместимости при необходимости.
5. После успешной проверки ключ шифруется и привязывается к workspace.
6. UI показывает только маску и статус подключения, но не полный ключ.

### FR-KEY-02 — Актуальный способ аутентификации
- Использовать действующую официальную документацию Google Gemini API и поддерживаемый SDK **Google Gen AI SDK** (`@google/genai` для Node.js/TypeScript либо `google-genai` для Python), с проверкой актуальности версий при реализации.
- Для прямого REST-вызова использовать официальный механизм API-key authentication, например заголовок `x-goog-api-key`, если он остаётся документированным Google на момент реализации.
- Не использовать устаревшие SDK и примеры интеграции, включая `@google/generative-ai` и прежний пакет `google-generativeai`.
- Не использовать OAuth-токен, service-account JSON или Vertex AI credentials в качестве замены пользовательскому Google AI Studio API-ключу.
- Не создавать собственный «новый формат» строк ключа: синтаксис ключа определяет Google; проверять ключ реальным запросом, а не только регулярным выражением или предполагаемым префиксом.
- Не передавать ключ в URL/query string, клиентский bundle, localStorage, логи или аналитику.

### FR-KEY-03 — Безопасность и жизненный цикл
- Шифрование at rest через KMS/secret manager; доступ к расшифровке только у backend-сервиса запросов.
- TLS при передаче; строгая изоляция tenant/workspace.
- Поддержка ротации, повторной проверки, удаления и отключения ключа.
- При удалении ключа новые AI-запросы блокируются; зашифрованный секрет удаляется согласно политике retention.
- Статусы: `not_connected`, `validating`, `active`, `invalid`, `quota_exceeded`, `revoked`, `temporarily_unavailable`.
- Никогда не возвращать полный ключ через API после сохранения.
- При 401/403 показывать ошибку доступа, при 429 — лимиты/квоты, при 5xx — временную проблему провайдера; не раскрывать ключ в ошибках.

## 7. Функциональные требования

### FR-AGENT — Конструктор агента
- CRUD агентов в workspace.
- Поля: название, описание, системные инструкции, язык, тон, выбранная модель, приветствие.
- Ограничения поведения: отвечать в рамках базы знаний, уточнять неоднозначные вопросы, передавать оператору чувствительные или неподтверждённые запросы.
- Предпросмотр конфигурации до публикации; история изменений.

### FR-KB — База знаний
- Добавление FAQ, текста, PDF и URL; контроль размера и типа файлов.
- Извлечение текста, разбиение на фрагменты, создание поискового индекса.
- Выбор embeddings-провайдера и способа индексации отдельно от генеративной модели; совместимость и расходы проверяются до включения.
- Метаданные: источник, дата обновления, версия, workspace_id.
- Редактирование, переиндексация, удаление источника и его фрагментов.
- Защита от prompt injection внутри загруженных документов и внешних страниц.

### FR-CHAT — Диалоги
- Потоковая выдача ответа при поддержке выбранной модели.
- История переписки с серверным хранением и настраиваемым сроком хранения.
- Источники/цитаты для RAG-ответов; маркировка неопределённости.
- Обратная связь 👍/👎, повторная генерация по запросу оператора.
- Эскалация человеку по правилам, кнопке клиента или недостаточной уверенности.
- Статусы: `open`, `ai_handling`, `waiting_for_agent`, `human_handling`, `resolved`.

### FR-WIDGET — Встраиваемый виджет
- Встраивание через публичный widget ID, не содержащий секретов.
- Настройка брендинга, языка и приветствия.
- Защита от спама, rate limiting, проверка разрешённых доменов (не как единственная мера защиты).
- Доступность с клавиатуры и адаптивность для мобильных устройств.

### FR-INBOX — Рабочее место оператора
- Очередь обращений, фильтры, назначение ответственного.
- Полный контекст эскалации и предложенный AI-черновик.
- Ручной ответ, закрытие и повторное открытие обращения.

### FR-ANALYTICS — Аналитика
- Объём диалогов, среднее время ответа, эскалации, оценки качества.
- Расход токенов и оценка стоимости при наличии официальных тарифов и данных usage.
- Разделять фактические данные провайдера и расчётные оценки.

## 8. Пользовательские сценарии

**UC-01: Первый запуск**  
Владелец регистрируется → создаёт workspace → вводит ключ Google AI Studio → система проверяет доступные модели → владелец выбирает поддерживаемую модель → загружает FAQ → тестирует агента → публикует виджет.

**UC-02: Ответ клиенту**  
Клиент отправляет вопрос → система проверяет лимиты → ищет релевантные источники → формирует запрос Gemini → возвращает ответ с цитатами → сохраняет диалог и метрики.

**UC-03: Эскалация**  
Агент не находит достоверный ответ или срабатывает правило → создаётся задача оператору → оператор получает историю и отвечает → диалог помечается как решённый.

**UC-04: Истёкшая квота**  
Gemini API возвращает ошибку квоты → запрос не зацикливается → владелец получает уведомление → клиент видит нейтральное сообщение и вариант связи с оператором.

## 9. Архитектура

```text
Customer Browser → Chat Widget → API Gateway
                                   │
                              Auth / Rate Limit
                                   │
                      Conversation Orchestrator
                        ├── Workspace / RBAC
                        ├── Knowledge Retrieval → Vector Store
                        ├── Prompt & Safety Layer
                        ├── Secret Manager / KMS
                        ├── Gemini Provider Adapter → Official Gemini API
                        └── Event / Usage Logger
                                   │
                         PostgreSQL + Object Storage

Admin Dashboard → Backend API → Workspace / Agents / Knowledge / Inbox
```

### Рекомендуемый стек
- Frontend: Next.js, TypeScript, React.
- Backend: NestJS или FastAPI; единый серверный Gemini adapter.
- DB: PostgreSQL; векторный поиск через pgvector при подходящем масштабе.
- Queue: Redis + BullMQ или эквивалент для индексации и фоновых задач.
- Files: S3-compatible object storage.
- Secrets: управляемый KMS/Secret Manager.
- Monitoring: OpenTelemetry, централизованные метрики и алерты.

### Ключевые правила
- Браузер никогда не вызывает Gemini API с личным ключом пользователя.
- Все вызовы Gemini проходят через backend, который извлекает ключ по авторизованному workspace_id.
- Tenant isolation применяется к SQL, векторному поиску, файлам, очередям и событиям.
- Секреты не передаются в промпт, трассировки или сторонние инструменты.

## 11. API (черновой контракт)

| Метод | Путь | Назначение |
|---|---|---|
| POST | `/v1/workspaces` | Создать workspace |
| POST | `/v1/provider-credentials/google` | Подключить ключ |
| POST | `/v1/provider-credentials/google/validate` | Проверить ключ |
| DELETE | `/v1/provider-credentials/google` | Отключить и удалить ключ |
| GET | `/v1/models` | Список моделей, доступных текущему workspace |
| POST | `/v1/agents` | Создать агента |
| PATCH | `/v1/agents/{id}` | Изменить настройки |
| POST | `/v1/agents/{id}/knowledge` | Загрузить источник |
| POST | `/v1/conversations` | Создать диалог |
| POST | `/v1/conversations/{id}/messages` | Отправить сообщение |
| POST | `/v1/conversations/{id}/handoff` | Передать оператору |
| GET | `/v1/analytics/overview` | Получить метрики |

**API security:** авторизация для административных запросов; отдельные краткоживущие токены с ограниченными правами для публичного виджета; idempotency для повторяемых операций; rate limiting и аудит.

## 13. Нефункциональные требования

- **Безопасность:** OWASP ASVS как ориентир, защита от XSS/CSRF/SSRF, контроль загрузок и инъекций в промпты.
- **Конфиденциальность:** минимизация PII, настраиваемый retention, экспорт и удаление данных, разграничение доступа.
- **Производительность:** p95 первого ответа ≤ 10 сек при нормальной нагрузке; внешняя задержка Gemini измеряется отдельно.
- **Масштабирование:** stateless API, фоновые workers, очереди и лимиты по workspace.
- **Надёжность:** ограниченные retries с exponential backoff для временных ошибок; circuit breaker.
- **Наблюдаемость:** трассировка запросов с редактированием чувствительных полей; оповещения по ошибкам и квотам.
- **Доступность интерфейса:** WCAG 2.2 AA как целевой уровень.
- **Совместимость:** только актуальные стабильные официальные API/SDK, версии зависимостей закрепляются и регулярно обновляются.

## 14. Безопасность AI

- Системные инструкции и права доступа не переопределяются пользовательским сообщением или текстом базы знаний.
- Любые внешние источники рассматриваются как недоверенные данные.
- Запрещено раскрывать системные промпты, API-ключи, секреты или данные других workspace.
- Ответы по чувствительным сценариям должны содержать безопасные ограничения и, при необходимости, передачу оператору.
- В MVP агент не совершает необратимых действий без явного подтверждения уполномоченного человека.
- Сохраняются причины эскалации, отказы провайдера и результаты проверки качества без раскрытия секретов.

## 15. Критерии приёмки

| ID | Условие | Ожидаемый результат |
|---|---|---|
| AC-01 | Новый workspace без ключа | AI-генерация заблокирована, показано подключение BYOK |
| AC-02 | Введён действительный ключ | Ключ проверен, сохранён зашифрованно, UI показывает маску |
| AC-03 | Введён недействительный ключ | Понятная ошибка, ключ не активируется |
| AC-04 | Пользователь запрашивает модели | Показаны только реально доступные и совместимые модели |
| AC-05 | Gemini 3.5/3.6/3.8 отсутствует в каталоге | Модель недоступна для выбора; выдуманные model_id не используются |
| AC-06 | Пользователь A пытается получить ключ B | Доступ отклонён, секрет не раскрыт |
| AC-07 | Клиент задаёт вопрос по FAQ | Ответ основан на источнике, при возможности содержит ссылку |
| AC-08 | Источника для ответа нет | Агент не придумывает факты и предлагает эскалацию |
| AC-09 | Google возвращает 429 | Нет бесконечных повторов; показано состояние квоты |
| AC-10 | Владелец удаляет ключ | Новые AI-запросы с ним невозможны |
| AC-11 | Проверка frontend bundle и логов | Ключи и другие секреты отсутствуют |
| AC-12 | Смена модели | Следующий запрос использует явно выбранный доступный model_id |

## 16. План реализации

### Этап 1 — Foundation
Auth, workspace, RBAC, схема данных, инфраструктура, KMS, журнал аудита.

### Этап 2 — Gemini BYOK
Подключение ключа, валидация, каталог моделей, Gemini adapter, ошибки и квоты.

### Этап 3 — AI Agent + RAG
Конструктор, база знаний, индексация, retrieval, генерация с источниками.

### Этап 4 — Support Operations
Виджет, Inbox, эскалации, история диалогов, аналитика.

### Этап 5 — Hardening & Pilot
Security review, нагрузочное тестирование, тестирование изоляции tenant, UX-пилот и релиз.

| Квоты и ограничения индивидуальных ключей различаются | Персональная диагностика, лимиты, понятные сообщения |

| Утечка BYOK-секретов | KMS, backend-only доступ, редактирование логов, тесты безопасности |
| Недостоверные ответы | RAG, цитирование, оценка качества, эскалация |
| Prompt injection через URL/PDF | Санитизация, trust boundaries, ограничение инструментов |
| Рост стоимости и задержки | Usage analytics, квоты, кэширование там, где безопасно |
